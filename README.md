# transcript-cosmolet

Конвейер для расшифровки записей носимого диктофона (Plaud), который пишет весь день.
Аудио забирается из облака, речь находится локально, транскрибируется с диаризацией,
говорящие опознаются по базе голосов, а на выходе — markdown-транскрипт, где у каждой
реплики есть имя, уверенность и абсолютное время. Написан Claude Code для собственного
использования. В репозитории только код: записей, голосов и имён здесь нет.

## Идея

Запись длится 8–12 часов, а речи в ней мало: на ночной записи — около 2–3 % длительности.
Платить за транскрипцию всего файла бессмысленно, поэтому конвейер делит работу так:

- **локально и бесплатно** — поиск речи (Silero VAD + классификатор аудио-событий CED),
  голосовые эмбеддинги (CAM++), кластеризация реплик и матчинг по базе голосов;
- **платно и только по речевым регионам** — транскрипция с диаризацией (ElevenLabs Scribe)
  и дешёвая LLM-судья для спорных реплик (через OpenRouter);
- **дневной бюджет** `DAILY_BUDGET_USD` — как только расход за сутки достигает лимита,
  платные этапы не стартуют, а ждут следующего дня; очередь ничего не теряет.

## Как устроено

```
Plaud cloud ─── sync (раз в 15 мин) ──▶ recordings: pending_download
                                              │
 download ──▶ data/audio/<файл>  (+ <файл>.meta.json: название, время начала)
                                              │
 detect ────▶ detect.json   карта речи: Silero VAD + CED, локально
                                              │
 quality ───▶ quality.json  Scribe: текст + анонимные speaker_0, speaker_1… (только речь)
                                              │
 resolve ───▶ resolve.json  CAM++-векторы реплик → кластеры → имена из базы → LLM-судья
                                              │
 store ─────▶ Postgres (segments, conflicts) + transcript.md + SCHEMA.md
```

Очередь — это таблицы `recordings` и `jobs` в Postgres, отдельного брокера нет.
Этапы связаны только артефактами на диске (`data/artifacts/rec_<id>/`), поэтому любой
этап можно переиграть, не трогая остальные.

Каждый этап живёт в своём контейнере (`docker-compose.yml`): `db` (pgvector/pg16),
`worker-download`, `worker-detect`, `worker-quality`, `worker-resolve` и `ui`.
Образ у воркеров один, различаются они ролью `WORKER_ROLE`. Разнесены намеренно:
пересборка кода одного этапа не обрывает работу других, а по сигналу остановки воркер
перестаёт брать новую работу и доводит начатую до конца (`stop_grace_period`).
Локальные этапы работают с пониженным приоритетом (`WORKER_NICE`), чтобы не мешать
машине, на которой конвейер крутится.

Вход не обязан быть Plaud: любой аудиофайл (m4a, mp3, wav, ogg, opus, webm, flac, mp4, mov),
положенный в `data/inbox/`, попадает в тот же конвейер. Рядом можно положить sidecar
`<файл>.meta.json` с полями `title` и `started_at` (ISO) — тогда у записи будет
человеческое название и абсолютное время. `fetch_plaud.py` делает такую пару по ссылке.

### Опознание говорящих (resolve)

1. Для каждой реплики Scribe длиннее 1.5 с считается 192-мерный вектор голоса
   (sherpa-onnx, CAM++). Короче — не измеряем: спикер наследуется от кластера и честно
   помечается `inherited`.
2. Реплики кластеризуются по косинусу через всю запись. Метки провайдера — только
   подсказка: Scribe умеет склеить двух людей в один `speaker_id`. Порог склейки
   подбирается под конкретную запись автоматически, а внутри длинных реплик ищется
   смена говорящего по границам слов.
3. Кластеры и отдельные реплики сравниваются с базой голосов (`speakers`,
   `speaker_samples`, pgvector). Уверенно — имя; неуверенно — `ambiguous` с разворотом
   кандидатов; неизвестные голоса — `S1`, `S2`…
4. Спорные реплики судит дешёвая LLM по контексту диалога (кто говорит о себе, к кому
   обращаются). Что не сошлось — попадает в очередь `conflicts` на ручной разбор в UI.

Все пороги лежат в `worker/config.py` с пояснениями, на чём они подобраны.

### Формат транскрипта

```
**[00:12:34 21:58:07] Alice Example · 0.91:** текст реплики
**[00:12:41 21:58:14] неизвестный (S2) · 0.48 ⚠️:** текст спорной реплики
```

В скобках — смещение от начала файла и абсолютное местное время (`LOCAL_TZ`), затем имя,
косинусная близость к эталону и `⚠️` у спорных реплик. Рядом с транскриптом лежит
`SCHEMA.md` с описанием полей разворота (`top`, `cluster_default`, `reason`, `judge`,
`resolution`). В базе у сегмента есть ещё пословные таймстемпы и `asr_logprob` —
уверенность ASR в тексте, которая не связана с уверенностью в спикере.

## UI

FastAPI + одна страница, доступна только с локальной машины: `http://127.0.0.1:8090`.

- записи и этапы с телеметрией и расходами, загрузка пулов, остатки на счетах провайдеров;
- транскрипт с прослушиванием любого фрагмента и JSON-артефактами этапов;
- очередь спорных реплик; ручные решения живут в `manual_labels` отдельно от сегментов
  и переживают переигрывание опознания;
- база голосов: люди, их сэмплы (включить, выключить, удалить), заметка о человеке;
- enroll — завести нового человека из неопознанного кластера прямо из записи;
- разбор неизвестных голосов через все записи разом и массовое назначение имени;
- подбор порога склейки под запись и пересборка `transcript.md` из базы после правок
  (`worker/export.py`), без повторного опознания.

## Запуск

Нужны Docker с compose, модели в `./models` и ключи провайдеров.

1. Модели (монтируются в контейнеры только для чтения), все — из релизов
   [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases):
   - `campplus_zh_en_advanced.onnx` — CAM++ speaker embedding, 192 float
     (релиз `speaker-recongition-models`);
   - `silero_vad.onnx` (релиз `asr-models`);
   - каталог `sherpa-onnx-ced-tiny-audio-tagging-2024-04-19/` (релиз `audio-tagging-models`).

   Имена файлов переопределяются через `EMBED_MODEL`, `VAD_MODEL`, `TAG_MODEL`.
2. `cp .env.example .env` и заполнить ключи (см. таблицу ниже).
3. Синхронизация с Plaud: публичного API у Plaud нет, конвейер ходит тем же путём, что
   официальный CLI. На хосте один раз выполнить `plaud login` — файл `~/.plaud/tokens.json`
   монтируется в контейнер, токен обновляется по refresh-токену сам. Без Plaud —
   `PLAUD_SYNC=0` и файлы в `data/inbox/`.
4. `docker compose up -d --build`.

Каталоги в `data/`: `inbox` (вход), `audio` (постоянное хранилище, не удаляется),
`artifacts/rec_<id>/` (`detect.json`, `quality.json`, `resolve.json`, `transcript.md`,
`SCHEMA.md`), `speakers/` (клипы-эталоны голосов).

## База голосов

В начале база пуста, и все говорящие — `S1`, `S2`… Заполняется тремя способами:

- **enroll в UI** — из кластера записи, который вы узнали на слух;
- `seed_speakers.py` — разовый импорт базы `voiceprints` из
  [claude-transcribe-mcp](https://github.com/vsmelov/claude-transcribe-mcp): клипы
  копируются в `data/speakers/`, SQL с именами и векторами пишется в `data/` (не в git);
- `import_clips.py` — считает эмбеддинги нарезанных клипов внутри контейнера воркера
  и добавляет их в `speaker_samples`.

Эталон человека — среднее нормированных векторов его активных сэмплов; референсный клип
для API-диаризации — 2–10 секунд чистой речи.

## Настройки (`.env`)

| Переменная | Что делает |
|---|---|
| `OPENROUTER_API_KEY` | LLM-судья спорных реплик (`JUDGE_MODEL`, по умолчанию `google/gemini-2.5-flash-lite`) |
| `ELEVENLABS_API_KEY` | транскрипция с диаризацией (`SCRIBE_MODEL`, по умолчанию `scribe_v2`) |
| `OPENAI_API_KEY` | остаток на счёте в UI |
| `DAILY_BUDGET_USD` | предохранитель: дневной лимит на платные этапы |
| `POSTGRES_PASSWORD` | пароль базы внутри compose |
| `LOCAL_TZ` | зона для абсолютного времени в транскриптах (Plaud отдаёт начало записи в UTC) |
| `PLAUD_SYNC`, `PLAUD_SYNC_EVERY_SEC` | синхронизация с облаком Plaud (вкл/выкл, период) |
| `DOWNLOAD_WORKERS`, `DETECT_WORKERS`, `QUALITY_WORKERS`, `RESOLVE_WORKERS` | размеры пулов по этапам: сеть и API — отдельно от CPU |
| `WORKER_NICE`, `ONNX_THREADS` | приоритет локальных этапов и потоки на модель |
| `DRAFT_MODEL`, `DRAFT_LANGUAGE` | whisper-черновик через OpenRouter — прежний детектор речи, оставлен для скриптов сравнения |

## Стоимость

Платят только два этапа: Scribe — около $0.22 за час **речи** (не записи), судья —
центы за запись. Детектор, эмбеддинги и кластеризация бесплатны. Все траты пишутся в
таблицу `costs`, UI показывает расход за день и остатки на счетах.

## Данные и приватность

`data/`, `models/` и `.env` в git не попадают. Вспомогательные файлы с именами и
векторами реальных людей (`seed_speakers.sql`, `enrich_clips.json`,
`enrich_voiceprints.py`) исключены в `.gitignore` намеренно. Всё хранится на одной
машине, UI слушает только loopback, внешним сервисам уходят только речевые регионы.

## Скрипты-эксперименты

- `vad_experiment.py` — сколько речи в ночной записи и насколько устойчивы голоса
  в найденных кусках (запускается внутри контейнера воркера);
- `tune_speechmap.py` — подбор полей и склейки регионов карты речи по правде от Scribe;
- `compare_models.py` — расходятся ли тексты whisper-черновика и Scribe на одних окнах.

Whisper-черновик был первым детектором речи: на 11-часовой ночной записи он пометил бы
речью 86 % длительности против реальных 2.6 % у VAD + CED, к тому же стоил денег и
галлюцинировал на тишине. Поэтому детектор локальный.
